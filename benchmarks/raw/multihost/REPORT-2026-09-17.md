## Canonical lane restored

The 2026-09-15 run was forced into **measure-only** mode: velqu failed 2
fixture assertions on both hosts (`POST /users bytes`, `C4 bytes`) because
the generated response encoders emitted object keys byte-sorted. That is
fixed in `f716c153` (encoder programs now compile provable declaration
order via `propertyOrder`; only unknown-field membership lookup stays
byte-sorted). This run therefore executed the **canonical fail-closed
lane**: on all three hosts every candidate's checker passed before any
timing, and no run carries a measure-only marker in its hashes file.

## Disclosed deviations and incidents

1. **Reconstructed host identity files.** The launcher session was
   interrupted mid-run on the local and Halotec hosts (a session restore
   killed the wrapper shells after the fixture checkers had passed). The
   measurement containers are daemon-managed and completed independently,
   writing complete artifacts (300 rows, summary, hashes). `host-local.txt`
   and `host-halotec.txt` were reconstructed post-run from the same hosts
   with the same commands `run.sh` uses; each file carries an embedded
   note saying so. Checker PASS is additionally provable from the
   preserved harness logs: the lane is fail-closed, and both logs show the
   checker section completing and the timed harness starting.
2. **Oracle CPU-limit deviation.** `run.sh` passes `--cpus=2`; rootless
   crun on the Oracle host rejects it ("controller `cpu` is not available"
   — the cgroup CPU controller is not delegated to the user slice). The
   recorded run was launched manually without `--cpus`/`--memory`; the
   container inherits the 1-vCPU VM, the same effective ceiling as the
   2026-09-15 run. Recorded in `host-oracle.txt` (`cpus-limit=none` plus
   note). No host cgroup/system configuration was modified.
3. **Oracle artifact-copy incident.** An intermediate Oracle rerun
   completed all five repetitions but produced no durable evidence: the
   final artifact copy failed because SELinux (Enforcing) denied the
   bind-mount write, and the container had been started with `--rm`, so
   its internal copy was destroyed with it. Its numbers were never read;
   no row of the recorded run comes from it. The final run used the `:Z`
   relabel and a named container (kept until artifacts were verified).
   `:Z` relabeled the SELinux xattrs of the Oracle raw directory — file
   contents untouched.
4. **Halotec buildx quirk.** A stale root-owned
   `~/.docker/buildx/activity/default` blocked the first build; worked
   around with an isolated `DOCKER_CONFIG` directory. No file was mutated
   or deleted.
5. **Cross-run comparison caution.** The 2026-09-15 COMPARISON rows
   measured `a72edc75` under the measure-only lane; the 2026-09-17 rows
   measure `f716c153` under the canonical lane. Same-host across-day
   deltas are descriptive only — host noise, different day, different
   lane mode. They are NOT a code-change benchmark; that requires the
   matched interleaved A/B protocol (see the C3 probe lane).
