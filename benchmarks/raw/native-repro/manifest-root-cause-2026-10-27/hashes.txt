## Conclusions

1. Reproducibility is sound: same commit + same mode + same toolchain
   reproduces byte-exact across six weeks and across checkout paths. No
   toolchain drift on the capture host.
2. The build-mode split is real and inherent: package-pair and workspace
   builds of the same tree differ (34076ab6 vs 1a5888fc at 1638c44;
   11012a5f vs e8701319 at HEAD). The first mode switch in a target dir
   recompiles ~108 dependency units under different feature unification;
   subsequent mode switches are relink-only.
3. The 2026-09-16 manifest refresh ran standalone, without a benchmark
   recapture: it bound 2026-09-10 evidence (harness binary c52385af...) to a
   2026-09-16 package-mode build at 1638c44 (34076ab6...). The manifest has
   been internally inconsistent since its creation.
4. scripts/verify builds workspace-mode and could therefore never reproduce
   the manifest hash at any commit: the byte-identity gate has been
   structurally unpassable since 2026-09-16 — ADR-0040's "a gate that cannot
   pass anywhere protects nothing".
5. The "actual 2d9b6866" hash cited in issue #1429 is not reproducible from
   any canonical build of 2990d3a0 (workspace: e8701319; package: 11012a5f);
   it came from a non-canonical build (packet-worktree dependency graph or
   composed ambient flags).
