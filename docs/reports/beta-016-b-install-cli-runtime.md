# BETA-016-B — Install CLI/runtime (external user)

## Overview

Acts as the external user inside the BETA-016-A fresh environment: from
a source archive only (no git checkout, no workspace links, no
prebuilt artifacts), performs the documented install path
(`docs/beta/INSTALL.md` Step 1) and proves the installed `velqu-runtime`
binary and unified CLI respond. The install lives entirely under
`$HOME` and is removable with one `rm -rf` (rollback/uninstall
guardrail).

## Deliverable

- `scripts/beta-external/install-cli-runtime.sh` — fail-closed external
  install: clean slate, extraction (with root-directory guard),
  `bun install --frozen-lockfile`, `cargo build --release -p
  velqu-runtime`, runtime `--help`, CLI `--help`; prints the uninstall
  path on success and an actionable step-numbered failure on error.
- `scripts/beta-external/Dockerfile` — carries the BETA-016-A
  environment plus one forward fix (tooling homes chowned to `beta`,
  see issues below).
- `scripts/beta-external/manifest.sh` — environment probe hardened
  with a writability check (`tooling_homes_writable=yes`).

## Issues and resolutions

1. **Archive without a root directory broke extraction.** The first
   `git archive` had no prefix, so `tar --strip-components=1` removed
   top-level files including `package.json`; `bun install` failed with
   "could not find a package.json file". Resolution: archives carry
   `--prefix=velqu/` (matching the BETA-015-A release-packet
   convention) and the script now fails with an actionable diagnostic
   naming the exact mismatch if extraction ever yields no
   `package.json`.
2. **Root-owned `CARGO_HOME` blocked the unprivileged install.**
   `cargo build` failed with "failed to create directory
   `/opt/cargo/registry/cache/...` Permission denied" because the
   BETA-016-A image kept tooling homes root-owned; the A probe missed
   it because `cargo --version` performs no writes. Resolution
   (forward fix carried in this packet): `chown -R beta:beta
   /opt/cargo /opt/rustup /opt/bun` in the Dockerfile, and the
   manifest probe now asserts writability of all tooling homes.
   Image rebuilt; new digest
   `sha256:9076de16f6ec3a64dadd9139a71e23bde01b1f67e49e6bd1572f96955a2f5570`.
3. Both resolutions verified by rebuilding the image, re-running the
   probe, and completing the full install to `INSTALL-OK`.

## Parent guardrails advanced

- **No local unpublished dependency** — the install resolves everything
  from the archive itself (workspace + lockfile) and the pinned
  toolchains; nothing outside the archive/host-toolchain is referenced.
- **Failures produce actionable diagnostics** — both failure modes
  found are now guarded with step-numbered, cause-naming errors.
- **Artifacts can be rolled back/uninstalled** — single-directory
  install under `$HOME`; uninstall path printed by the script.
